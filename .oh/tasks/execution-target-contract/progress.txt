# progress

## Codebase Patterns

- **The task folder is tracked but gitignored.** `.oh/tasks/<slug>/` matches a `.gitignore` rule,
  yet `prd.md` / `prd.json` / `progress.txt` are already tracked (added with `-f` when scaffolded).
  A plain `git add .oh/tasks/...` fails with "paths are ignored" AND aborts the whole `git add`
  invocation — including the non-ignored paths listed alongside it. Stage the task folder with
  `git add -f` in a **separate** command from the rest of the story's files.
- **Quality-check script names.** From the repo root: `pnpm run typecheck` (no hyphen; delegates to
  `npm --prefix .oh/cli run typecheck` → `tsc --noEmit`) and `pnpm test` (vitest, 39 files / 481
  tests, ~5s). `pnpm run type-check` does not exist. Root `lint` is a no-op.
- **New RFCs must be indexed in TWO places.** `.oh/docs/rfcs/README.md` (the `## Index` table) and
  `.oh/docs/README.md` (the flat RFC bullet list, ~line 74-78). CHANGELOG #686 records the repo
  paying for a missed index entry, so treat both rows as part of "create an RFC", not scope creep.
- **Ground-truth the socket/dockerd facts before citing them.** Verified this iteration:
  `.devcontainer/docker-compose.yml:20-26` states the host socket is NOT mounted by default;
  `.oh/scripts/docker-compose.sh:136` appends `docker-compose.docker-sock.yml` only when
  `truthy()` (`:63`) accepts `sandbox.docker_socket` / `DOCKER_SOCKET`; `.devcontainer/Dockerfile:37`
  installs `docker-ce-cli` + `docker-compose-plugin` and no `dockerd`.
- **The base compose bind is `..:${OH_PROJECT_ROOT:-/home/sandbox/harness}`** — a host path mapped
  to a fixed in-target path, so host and target paths are NOT identical in general. The RFC's
  "identical-path mapping only" stance is therefore a **contract-level** restriction (nothing above
  the seam translates paths; `resolveProjectRoot` yields one string used for both file reads and
  compose invocation), not a claim about the compose file. Do not restate it as a deployment fact.

### Learnings for future iterations

- **US-005's probe C2 has a pinned exclusion window.** The only Docker nouns in `target.ts` are on
  `:65` (`  | "docker"`) and its doc comment on `:64`. Implement C2 as: drop any line matching
  `\| "docker"` **and the single line immediately above it**, then grep the remainder
  case-insensitively for `container|compose|image|volume|dockerd|docker`. That exact awk filter is
  already dry-run green against the committed file. Do not write C2 as a whole-file grep with a
  `docker`-line-only exclusion — it would trip on the doc comment.
- **C3's grep must be `snapshot(`, not `snapshot`.** The capability literal and its doc comment both
  say "snapshot"; only the `(` distinguishes a method declaration. The doc comment is deliberately
  worded to avoid an adjacent open paren.
- **No CHANGELOG entry for US-002 — that is correct, not an omission.** US-002's AC list has no
  CHANGELOG criterion because a types-only internal file has no user-visible impact; US-004 carries
  the `### Changed` entry for the behavior-preserving reroute. Do not add a second entry.
- **US-003's DI seam already has two precedents to copy.** `RemoteRunner` (`lib/remote.ts:33-37`) and
  `LifecycleRunner` (`commands/lifecycle.ts:49-53`) are the same shape:
  `(cmd, args, opts) => RunResult` with a module-private `spawnRunner` default and an optional
  `run?` option on the public options interface. `lib/remote.ts`'s `RunResult` **already has
  `stderr?: string`** (`:29`) — so US-003's additive `stderr?` on the lifecycle `RunResult` is
  matching an existing in-repo convention, not inventing one.
- **`ExecRequest.stdio`'s default is deliberately left to the implementation** ("Omitted → the
  implementation's documented default"). US-003 may pick the adapter's default freely without
  contradicting the contract.
