## Codebase Patterns

- **`node --test <dir>` does not work in this sandbox** (node v22.23.2). It fails
  with `Could not find '.'` / `MODULE_NOT_FOUND` on the directory path. Reproduced
  on a clean `mktemp -d` fixture and on the pre-change tree, so it is environmental,
  not a repo defect. Use the file-glob form:
  `node --test .oh/skills/prompt-miner/scripts/__tests__/*.test.mjs` (exit 0).
  Any AC that pins the directory form must be read as "the suite passes".
- **`.oh/skills/**` is not in the vitest globs** (`vitest.config.ts:5-9`), so this
  suite never runs in CI. Every test AC here is verified by explicit invocation.
- **Root quality scripts**: `pnpm run typecheck` (NOT `type-check`), `pnpm run lint`
  (a no-op echo at root).
- **`scoreSession` is pure** — it takes a plain `agg` object, so worst-case inputs
  that `aggregateSession` can never produce (e.g. `abandoned` and `incomplete` both
  1, which the aggregator makes mutually exclusive) can be exercised with a literal.
- **Fixture split**: the three fixtures all rank by default. Pass `--min-turns 4` to
  push the 3-turn `claude-good` session into `unranked[]` when a test needs both
  populations non-empty. `--no-git` means no session earns the ground-truth bonus,
  so no fixture session exceeds 100 uncapped without a synthetic `scoreSession` call.

### What I did

Added `scoreUncapped = Number((base + bonus).toFixed(2))` to `scoreSession`'s return
value as a sibling of `score` (not nested in `scoreBreakdown`), and threaded it onto
the session record built at `mine-traces.mjs:1026` — one call site before the
rankable/unranked split, so it lands on both `sessions[]` and `unranked[]`. `score`
itself is untouched: still `clamp(base + bonus, 0, 100)`. Added four tests: the
ceiling case (`score === 100` while `scoreUncapped === 115`), the floor case (all
five signals at max → `scoreUncapped === 0`, no negative producible under the current
weights), a fixture run asserting `scoreUncapped` on both populations, and a control
pinning that `sessions[]` still sorts by clamped `score` descending.

Verified R7 by `git diff`: `DEFAULT_WEIGHTS`, the penalty arithmetic, `SCORE_MODEL`,
and `MARKER_FEATURE_KEYS` are all absent from the diff. The whole change is +7 lines
of engine, additive.

### Learnings for future iterations

- **The attribution check passed**: deleting the `scoreUncapped:` line from
  `scoreSession` turns 3 of the 4 new tests red (exit 1). The 4th (ranking order) is
  a deliberate control that stays green — it pins behavior the change must NOT alter.
- **The pinned test command in US-001's ACs is unrunnable here.** See Codebase
  Patterns. I did not "fix" the AC or the environment; I ran the equivalent glob form
  and recorded the deviation in `prd.json` `notes`. US-002 and US-003 pin the same
  command and will hit the same wall.
- `abandoned` and `incomplete` are **mutually exclusive** in `aggregateSession`
  (`incomplete = !clean && !abandoned`), and `correctionDensity` counts follow-ups
  only, so it is always `(n-1)/n < 1`. A "maximally penalized" session cannot be
  built from an event list — use a literal `agg`.
- US-002 needs a fixture with a `noHumanPrompt` session (`sessionType` null) to pin
  that no `null` key appears in `ceilingSaturation`. The current fixtures have none;
  that story will need to add one, or construct the dataset in-process.
- CHANGELOG is owned by US-003, not this story — no entry added here.
