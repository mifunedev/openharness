## Codebase Patterns

- Worktree is `.oh/worktrees/spec-simplification` on `feat/spec-simplification`, based on `development` at 60f8c12d (after PR #815 merged). The MAIN checkout at `/home/sandbox/harness` is on `development` and had a live session in it — do not check this branch out there.
- `.oh/tasks/*` is gitignored (`.gitignore:12`). Task-folder files need `git add -f`. A bare `git add` on that directory silently stages nothing — that defect is US-006's fix, inherited from `ship-spec/SKILL.md:294`.
- `.claude/skills` is a symlink to `../.oh/skills`, so `.claude/skills/<x>/` and `.oh/skills/<x>/` are the same files. Probes reference the `.claude` path.
- `CLAUDE.md` is a symlink to `AGENTS.md`. A probe asserts the symlink is unsevered.
- Writing a file whose content mentions a release/version state machine can trip the cc-safety-net analyzer on a `cat > file <<EOF` heredoc. Use the Write tool for those, not Bash.
- A shell command whose text contains `.env` as a substring is denied by the secret-exposure guard. A `.config` path segment is denied outright for every tool. Split the string or use `-F file`.
- `.oh/skills` tests are excluded from the vitest globs, so `node --test` suites under `.oh/skills` never run in CI. A test-based acceptance criterion there is unenforceable — prefer a probe.
- The probe suite is 106 files. `bash .oh/skills/eval/run.sh` is the runner. As of planning it was 7 days stale (RESULTS.md was touched 2026-08-23 but every row's last-run reads 2026-08-16) and sat at 102 PASS / 4 SKIPPED / 0 REGRESSION.
- Verify a probe by rejection: feed it input it must reject and confirm the failure is attributable to the assertion under test. Exit 0 proves nothing.
- Never run a destructive verification against the live slug. `.oh/scripts/firstmate.sh --kill <this-slug>` stops THIS session (US-002 learned it the hard way). Build a decoy in a temp git root with `RUNNER_TMPDIR` redirected, and assert on that.
- The probe suite is 107 files after US-002 (+2 new, -1 whose subject was deleted). Baseline after US-002: 103 PASS / 4 SKIPPED / 0 REGRESSION.
- When a rule MOVES between surfaces, its probe moves with it. Deleting the probe because its old file no longer matches loses the lesson; repoint it at the new owner and assert BOTH the rule there and the deferral where it used to live.

### Learnings for future iterations
- **Four probes went red, not three.** `audit-dispatcher-contract.sh:26` carried
  `critique` and `approve` in its "retained instrument" list — nothing in the PRD named it.
  Run the full suite BEFORE assuming the PRD's probe inventory is complete.

- The `/critique` grep pattern also matches the *path* `.oh/tasks/<slug>/critique.md`, so a
  no-residue sweep must cover every doc that names that artifact — `/teach`, the ralph
  prompt template, and the `/ship-spec` handoff/compact text all did.
- `.claude/protected-paths.txt:71` listed `references/critique.md`. A protected-path entry
  must be removed in the same change that deletes the file, or the path guard fires later
  with no context.
- **Stated deviation from AC-7 (grep returns hits only in `CHANGELOG.md`).** Three classes
  of hit remain and were left deliberately:
  1. `.oh/tasks/**` completed-run artifacts (14 tracked `critique.md` files plus the
     `prompt.md`/`prd.md` of past runs). These are the historical record of what past
     builds produced — the same class as `CHANGELOG.md`, not a route an agent can follow.
  2. `.oh/evals/datasets/autopilot-runs/DS-010-*/oracle/changed-files.txt` — a frozen
     oracle of one historical run. Editing it falsifies the dataset.
  3. The rewritten probes' own negative assertions and the prose that states the gate is

  Two genuine false positives WERE fixed: `fetch/review/approve gate` in the grok-build and

### Learnings for future iterations
- **Verify a destructive path against a decoy, never the live slug.** The previous session
  killed itself proving its own `--kill` fix worked. `executor-kill-clears-session.sh`
  encodes the safe shape: a temp git root, `RUNNER_TMPDIR` redirected, and the slug

- **A probe that outlives its subject must move to the rule's new owner, not be deleted to
  green.** `eval-gate` guarded a lesson (pre-existing reds don't block) that migrated from
  autopilot §6 into `/ship-spec` Stage 11 when autopilot stopped running `/eval`. It now
  asserts the rule on ship-spec AND the deferral on autopilot, so relocating it again
  without moving the probe trips it.
- **A raw count assertion is Goodhartable.** `clean-restore` counted ≥4 scoped-restore
  sites; removing §6 left 3. Lowering the threshold alone would have let three restores
  sitting in prose satisfy it. Verified: a mutation that strips the restore from the
  `BUILD-INCOMPLETE` path *while holding the count at 3* is caught only by the added
  path-specific assertion.
- **Three probe surfaces went red that the PRD did not name** — `autopilot-upstream-default`
  (it read the deleted ralph prompt template), `clean-restore`, and `eval-gate`. Same lesson
  as US-001: run the full suite before trusting the PRD's probe inventory.
- **`RALPH_HARNESS` was live code, not prose.** The cron runtime exports it on the
  claude→codex fallback. AC-9's `RALPH_` grep forced a real rename to `FIRSTMATE_HARNESS`
  across `cron-runtime.ts`, its two test files, and a probe.
- **Six vitest tests pinned the removed behavior**, including one asserting the `| tee` pipe
  survived — the exact defect. A test that pins a defect must be rewritten in the same
  change that fixes it, or the fix cannot land.
- The foreground rung's session log path collides with the runner's own narrative log
  (`runner_log_path` and `runner_session_log_path` both yield `firstmate-<slug>.log`
  outside tmux mode). Assert on that file's CONTENT, not its existence.
- **Stated deviation from AC-9** (grep returns hits only in `CHANGELOG.md`). Three classes
  remain, deliberately, matching US-001's precedent:
  1. `.oh/evals/datasets/ship-spec-prs/DS-002-*/oracle/diff.patch` — a frozen oracle of a
