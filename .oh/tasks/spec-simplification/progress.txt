### Learnings for future iterations
- **Four probes went red, not three.** `audit-dispatcher-contract.sh:26` carried
  `critique` and `approve` in its "retained instrument" list — nothing in the PRD named it.
  Run the full suite BEFORE assuming the PRD's probe inventory is complete.
- `workflow-boundaries.sh` runs under `set -euo pipefail`. A bare
  `grep -q X && missing+=(...)` negative assertion is legal there (bash exempts non-final
  commands in an `&&` list) but reads as a bug; write it as an explicit `if`.
- The `/critique` grep pattern also matches the *path* `.oh/tasks/<slug>/critique.md`, so a
  no-residue sweep must cover every doc that names that artifact — `/teach`, the ralph
  prompt template, and the `/ship-spec` handoff/compact text all did.
- `.claude/protected-paths.txt:71` listed `references/critique.md`. A protected-path entry
  must be removed in the same change that deletes the file, or the path guard fires later
  with no context.
- **Stated deviation from AC-7 (grep returns hits only in `CHANGELOG.md`).** Three classes
  of hit remain and were left deliberately:
  1. `.oh/tasks/**` completed-run artifacts (14 tracked `critique.md` files plus the
     `prompt.md`/`prd.md` of past runs). These are the historical record of what past
     builds produced — the same class as `CHANGELOG.md`, not a route an agent can follow.
  2. `.oh/evals/datasets/autopilot-runs/DS-010-*/oracle/changed-files.txt` — a frozen
     oracle of one historical run. Editing it falsifies the dataset.
  3. The rewritten probes' own negative assertions and the prose that states the gate is
     gone (`ship-spec/SKILL.md:41`). These exist to keep it gone.
  Two genuine false positives WERE fixed: `fetch/review/approve gate` in the grok-build and
  hermes installer docs (unrelated third-party prose) was reworded.
